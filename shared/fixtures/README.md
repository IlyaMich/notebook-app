# FMT-03 — portable `.notebook` golden fixtures

Synthetic compatibility artifacts for the agreed Document Model V0.2 and **provisional** `schemaVersion: 1` wire format. These files do not encode real user content and are not production migrations.

## Checkpoint 1: positive mixed-content golden

`valid/mixed_pages_v1.notebook` is a **committed ZIP archive** containing a manifest, four ordered pages, and two hashed assets. It covers:

- A4 portrait ruled page with pressure-sampled pen stroke, transformed arrow, and styled Unicode text.
- US Letter landscape grid page with a cropped/partially opaque PNG image and a filled rectangle.
- US Letter portrait blank page with locked highlighter stroke and optional missing pressure.
- US Letter portrait `pdfPage` background referencing the **second** page of a valid two-page embedded PDF, with an independent editable text annotation.
- Stable UUIDs, ordered arrays, asset SHA-256 and byte lengths, immutable content-addressed asset paths, and UTC timestamps.

The source generator is `shared/fixtures/build_golden.py` and uses only the Python standard library. Binary output is **deterministic**: the tests compare regenerated bytes with the committed archive. Do not hand-edit the ZIP; edit the builder and review its compatibility implications before regenerating.

From the repository root, in Windows PowerShell:

```powershell
py -3 shared/fixtures/build_golden.py
py -3 shared/validators/validate_notebook.py shared/fixtures/valid/mixed_pages_v1.notebook
py -3 -m unittest discover -s shared/validators/tests -v
```

For CI, `shared/validators/tests/test_golden_fixtures.py` automatically exercises the committed fixture in the existing shared-format workflow.

## Scope and limitations

- Positive fixture validation does **not** show that Android or iPadOS can render or round-trip the archive. Those checks happen during later native implementation.
- The Python FMT-02 validator checks PDF asset references and signatures but does **not** currently verify PDF page count, `pageIndex` validity, PDF rendering or malformed PDF structures. This golden PDF was separately verified to have two pages during fixture creation; that does not add PDF parsing to the validator.
- Invalid/edge-case `.notebook` archives and expected rejection reasons are the **next FMT-03 checkpoint**; this change does not claim that the full #13 acceptance criteria are complete.
- The golden document must not contain notebook/folder library relationships; those belong in local database metadata, not portable page geometry.
