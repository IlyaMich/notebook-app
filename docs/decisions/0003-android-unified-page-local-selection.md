## Context

EDT-14's issue acceptance criterion is: **“Lasso selects ink, shapes, text, and images on one page; mixed move/scale is one operation.”** The V0.2 document model already requires page-local mixed selection by intersection, retention of editable canonical elements, and a logical atomic/undoable operation. The portable schema is a draft rather than a frozen interoperability guarantee.

The merged EDT-12 implementation supplies shape-only selection/editing, painted-geometry hit testing, page containment, cancellation, and guarded undo/redo. Ink and shape rendering already share persisted element order and page clipping. `DocumentRepository.commitIfRevision` and `RoomDocumentRepository` own the note revision and transactional command boundary; `NoteAutosaveCoordinator` owns one confirmed-commit history sequence. None of this constitutes a completed unified lasso.

Canonical text and image envelopes exist, but production text/image rendering and creation UX are not complete. `CNT-02` and `CNT-04` depend on EDT-14, so EDT-14 must prove selection/transform with **actual supported canonical text** and **actual verified, registered image elements** via synthetic/approved test setup; placeholders or bounding-box-only simulations are insufficient for acceptance.

STO-08 has merged Room v4 typed asset ownership and a narrowly guarded **insert-only** image writer. The `element_asset_references` table projects image `elementId → assetId`; canonical JSON remains authoritative. Generic `ReplaceElements` refuses image edits; image removal, transfer, media-aware purge, cleanup and UI attachment activation remain restricted. A geometry-only retained-image transform is structurally compatible with the unchanged reference, but has **no existing approved writer**. STO-08 is researching export snapshots; the four B1 research files are now committed on the collaborator's research branch only. Their provisional quotas are not production interfaces or evidence of test execution. No STO-08 B2/B3 execution is authorized by the research documentation.

## Decision (D1–D5 and INT-01–INT-06 accepted architecturally; implementation details remain gated)

### D1 — Page-local lasso membership and tap targeting

A completed lasso is a transient, implicitly closed polygon in **one owning page's document units**. Select eligible elements whose **visible painted geometry intersects** the region; bounding-box overlap alone is not sufficient for ink/open shapes. The stroke footprint must match the current retained renderer's effective paint, not an assumed future pressure-aware brush. For supported text/images, use the **transformed, clipped visual frame**, including transparent image pixels when the overall element opacity is nonzero. For concave/self-intersecting lassos, use even-odd interior; edge contact is intersection under a separately reviewed finite DU tolerance.

Locked elements, page backgrounds/templates, PDF backgrounds and fully transparent elements are not selectable by this tool (the latter is an explicit V1 tool limitation, not deletion or alteration). Unknown, malformed or unsupported content is preserved, never silently discarded. If visible geometry is unavailable and intersection **cannot be excluded reliably**, selection/transform admission for the affected page must fail with an explicit unavailable-element result; do not silently select only recognized neighbors. A safely excluded unavailable object outside the target region may be ignored only when exclusion is provable.

Tap selection targets the topmost eligible object in reverse canonical render order; handles have deterministic precedence and tie breaks. Use platform touch slop for distinguishing tap from a lasso **as an accepted architectural direction, with detailed thresholds still gated**, and retain EDT-12's 8 dp body-target tolerance where relevant. A lasso must pass the tap classifier and have nondegenerate area. Convert input thresholds through density and viewport transforms; geometric intersection tolerances are expressed in page DU independently of zoom. **Open for C1/C5 approval:** exact numerical DU boundary epsilon, accepted lasso workload limits and small-gesture policy. Do not mistake EDT-12's 4 dp creation threshold for an approved lasso threshold.

### D2 — Transient selection state and identity

Selection is **ephemeral**, not a portable document field or Room entity. It contains one active page, stable `(pageId, elementId)` references, canonical render ordering, a captured note revision/snapshot identity, and any drag baseline. Never silently retarget a stale ID to a different element or page. Revalidate against current stored/confirmed content on reload, page change, configuration recreation, external edit, and lifecycle restoration; clear or reject stale members. Configuration-change retention is permissible only if every member can be revalidated; otherwise clear selection. No cross-page lasso or implicit transfer.

### D3 — Affine group movement and proportional scaling

Compute one typed **page-space group operation** (`Translate(dx,dy)` or `UniformScale(anchor, positiveFactor)`) from the frozen original selection snapshot. Its affine `G` is left-composed with each original `T_before`: **`T_after = G × T_before`**, under the existing column-vector `[a,b,c,d,tx,ty]` convention. All members must share this same group operation; the repository derives output transforms rather than accepting unrelated caller-supplied new affines or replacement payloads. This applies to forward gestures; exact history restoration is defined in INT-05.

For uniform scaling, use a deterministic anchor/handle and derived union of **visible painted bounds for selection**, with separately validated **full (unclipped) painted footprints for forward containment**. Handle zero-area/tiny group bounds explicitly. Recompute every preview from frozen originals; never accumulate from successive transient previews. Preserve existing rotation, shear, reflection and all canonical payload values. Reject nonfinite/singular/overflowing transforms or unrepresentable painted results; require a finite inverse and renderable double-to-Canvas Float projection. Accepted architectural policy is positive finite scaling subject to those physical and numerical checks, **without imposing a new portable-schema scale range**; exact operational epsilon, scale/gesture workload limits, and anchor semantics require separate C1 approval.

Mixed scaling of text scales its glyphs and frame visually through the envelope affine while retaining font size, style and frame payload fields: never multiply the font size as well. This is not CNT-02 text reflow. Images preserve their source frame, optional crop, opacity and asset reference; only their displayed affine geometry changes. The retained renderer must apply complete transforms and clipping consistently.

### D4 — Page boundaries, clipping and transient preview

An input gesture captures page, pointer owner, viewport/camera/layout generation, relevant note revision and starting canonical snapshot. Page/viewport exit cancels the unfinished gesture, as in ADR-0002, with no implicit cross-page ownership. For **forward gestures only**, a previously fully contained group may commit only candidates whose **full, unclipped painted footprint** fits the owning page. Keep the last-valid contained preview while pointer ownership is valid, following the reviewed completion policy. For preexisting partly clipped groups, preserve source geometry unchanged on selection; a forward transform may commit when all members become fully contained, otherwise it is rejected. Clipped geometry participates only in visible selection, anchor derivation and paint.

**Exact undo/redo is not a forward editing gesture.** Restoring an original, previously clipped, committed transform must remain possible. Containment is a planner/admission rule for new forward transforms, **not** a generic repository/history constraint. The restricted history path validates exact expected-current snapshots, permitted saved targets, page/owner/asset/lock/revision consistency and representability; it cannot offer a public or free-form "skip containment" flag. This is required so the above conservative forward policy does not make a successful gesture permanently non-undoable.

During preview, substitute selected commands **at their original canonical paint-order positions**; do not lift selected members into an always-on-top layer. Maintain alpha compositing, page clipping and consistent hit/handle overlays.

### D5 — Input arbitration, cancellation and history admission

Extend the existing coordinated page-tool pointer ownership path; do not introduce competing gesture detectors. Lasso, ink, eraser, shape-edit and viewport navigation remain mutually exclusive. Preserve stylus priority, eraser-button routing, palm/finger arbitration and second-finger takeover: a viewport pinch must never scale content. Cancel on platform/consumed pointer cancellation, pause/disposal, relevant tool/settings/camera/layout/page/revision changes and stale member state; require a fresh down.

Selection, no-op and rejected previews never create note revisions or history. **One confirmed changed gesture = one guarded durable command = one chronological history entry.** Current `NoteAutosaveCoordinator` assumes admitted guarded actions advance the revision once; therefore, the implementation must prefilter no-op gestures before queueing and separately recognize a *confirmed repository no-op* if it occurs, without history or an unconfirmed-save state. It must distinguish **definite rejection**, **confirmed no-op**, **confirmed changed commit** and **unknown acknowledgement**. Unknown outcomes require reconciliation against durable state; no blind retry or false Saved. Undo/redo uses the same protected storage boundary, exact snapshots and top-entry chronology without skipping shape/eraser history. EDT-18's general clipboard/history system stays out of scope.

### INT-01 — Narrow, unified transform command (STO-08 integration)

Adopt the architectural direction of **one internal typed multi-element transform command** within `RoomDocumentRepository`'s existing transaction owner and revision-guarded path. A *forward plan* identifies one active note/page, exact nonnegative expected revision, a bounded distinct set of element IDs, **frozen expected complete canonical source envelopes** (or an equally strong exact-content equality guard), and one typed `Translate` or positive `UniformScale` operation. The repository compares current persisted source identity/content to expectations and **derives all new affine transforms itself**. It accepts no caller-authored arbitrary replacement JSON, image asset paths, independent per-member transforms or new media payloads.

An *internal exact history-restore plan*, admitted only through the coordinator's confirmed history entry, carries exact expected-current and recorded target transforms/envelopes and is independently validated. It is not a publicly callable arbitrary replacement or generic containment-bypass flag. The precise visibility/type boundary and parser/workload quotas require reviewed C3 design before code.

Only the guarded revision entry point may accept this command; unguarded `commit` must reject it. Generic `ReplaceElements` and other pre-existing commands continue rejecting image modifications. One mixed gesture must never split into media and non-media commits or use an independent transaction/undo service.

### INT-02 — Exact media ownership and non-geometry preservation

For **every** member, parse and validate the **complete supported canonical envelope and payload**, including type/kind, ID, valid unlocked Boolean, allowed fields, bounded representation and absence of hidden/unsupported media references. Require exact equality to the expected persisted canonical source and indexed kind/page/order, including page background and typed owner-edge consistency. Each selected **non-image** must have **no** `element_asset_references` edge. Unknown or malformed JSON is not evidence of absent media and never authorizes a mutation.

For each image, preserve identity, `payload.assetId`, page, order, locked state, frame, crop presence/value, opacity, all remaining envelope fields and payload **exactly**. Only its top-level six-value affine transform changes. Require exactly one matching `element_asset_references(elementId, assetId)` edge, a matching existing `finalized` asset row, valid supported PNG/JPEG MIME, a positive encoded length within the existing bound, lowercase 64-character SHA-256 and the exact MIME-dependent content-addressed relative path. These are **metadata/ownership consistency checks**, not proof that the file bytes currently exist or decode correctly. Require target-page background/typed page-edge consistency; reject an unsupported PDF background or inconsistent ownership on the first implementation, with no repair/backfill.

Never modify an image edge, metadata row, original file or gate to perform a geometry transform; never release/reinsert the edge. All other members retain their stroke samples, shape geometry, text style and other payload values byte-for-byte or semantically identically under an approved lossless representation. Reject locked, unsupported, inconsistent or unrepresentable members and roll back the entire mixed command. Generic `CanonicalContentValidator.element` must continue rejecting images; the new implementation needs a narrow, reviewed retained-image validation path, not a broad validator relaxation. Diagnostic asset inventory is not authorization.

### INT-03 — Transaction, revision, no-op and failure semantics

Within **one existing Room document transaction**, confirm active note/notebook, page ownership, supported page/background and ordering, exact caller expected revision and revision headroom; bound member count **and total validation work** (envelope bytes, stroke points, paths and geometry complexity), compare complete expected sources, and check all member payload/lock/owner-edge/metadata invariants and proposed transforms **before writing any row**. Forward containment was validated by the geometry planner against complete painted footprints and must be rechecked against a reviewed deterministic forward plan, but **must not be re-applied to exact history restoration**.

A changed operation updates exactly one persisted element row per member (checked affected-row counts) and advances note revision **exactly once** (checked note row count). Any stale baseline, invalid member, SQL error, cancellation or conflict rolls back the complete operation. A fully validated no-op returns the existing revision and leaves all rows/history unchanged. No-op must not be used to conceal a stale revision or invalid request. Results distinguish **definite rejection**, **confirmed no-op**, **confirmed changed commit** and **unconfirmed outcome**. The coordinator cannot call all failures "uncertain"; uncertain outcomes are reconciled before further editing, without replay or false Saved.

The forward command and exact guarded history restore share image/ownership validation. They do not perform media attachment, edge mutation or asset integrity certification; see INT-04.

### INT-04 — Retained-image verification and lease policy (**accepted architectural resolution; C2/C3 execution remains gated**)

**Accepted choice A for retained-reference geometry updates:** use **transaction-time database-only ownership validation** and do **not** acquire the asset acquisition lease merely to change an existing element affine. The command introduces/removes **no** durable asset reference, original byte read, file write or owner-edge change. Validate canonical JSON, exact typed edge, supported finalized asset **metadata identity**, target-page/owner consistency and gate together inside the guarded Room transaction, as specified in INT-02/03. A successful commit attests to **preserved canonical ownership**, **not** current on-disk byte existence, hash correctness, media readability or global ownership-index completeness.

**Accepted initial gate policy:** permit only an already committed, locally consistent retained image whose gate reads exactly `UNVERIFIED`; reject `UNRESOLVED`, `UNSAFE`, missing, duplicated, malformed or unexpected gate states. `UNVERIFIED` is not a cleanup/export permit, and no gate promotion/repair occurs. Review future gate additions separately; do not silently treat unrecognized new states as safe.

**Separate asset-read contract:** reading **managed original image bytes** to construct a retained render bitmap requires the separately approved shared acquisition lease and confined, verified, strict-bounded PNG or single-scan-baseline JPEG decoding. Painting an already independently verified, immutable cached bitmap does not itself reacquire the lease; cache identity, lifetime, aggregate memory limits and invalidation still require C2 design approval. A normal editor image-read must not treat this DB-only geometry outcome as a media integrity certificate. If source bytes are missing/corrupt or render geometry is unavailable, the UI must report unavailability and must not silently admit the image into a mixed lasso. Do not call image verification/registrar inside Room or nest the existing non-reentrant lease. A multi-image **read/verify** batch, if needed, requires one outer lease and a designed lease-aware reader rather than recursively calling per-image leased APIs.

Future STO-08 export snapshots must capture **one coherent old or new note revision/geometry/asset reference set** in their Room snapshot; the export lease protects source-copy integrity, not frozen future editing of geometry. A future approved reclaimer must regard still-retained active/Trash owners as ineligible, regardless of the image transform's lack of a lease. No export/GC implementation or concurrent race pass is claimed by this design. **Both developers accepted this separation on 2026-11-11; concrete APIs, budgets and C3 implementation authorization remain separately gated.**

### INT-05 — One chronological undoable operation

Record the **exact** confirmed before/after canonical envelopes or losslessly preserved recorded transforms, member IDs and order, and one chronological history entry **only after durable acknowledgement**. Undo/redo submits a guarded internal exact-restore operation that compares each expected-current member, revision, image ownership, lock, payload and order. It restores the **recorded** transforms and payloads directly, never by repeatedly applying an approximate inverse; it cannot bypass general media validation or mutate a reference.

The history restore **may legitimately reestablish previously clipped geometry** that was the persisted before/after state of a confirmed operation. It is not a general new forward gesture and does not use the forward containment admission rule. A history state whose current source, owner, gate or revision fails to match rejects safely, preserving confirmed content; unsafe history cannot be auto-skipped or executed by a public bypass. Coordinator no-op, committed, definitely rejected and unconfirmed outcomes retain the distinctions in D5/INT-03. Shape/whole- and partial-stroke eraser chronology remains intact.

### INT-06 — Protected scope and ownership

No general image replacement, asset substitution, image deletion, element transfer, attachment UI activation, PDF background edits, owner-edge repair, legacy certification/backfill, GC, original-file cleanup, export activation, schema/migration changes, or ownership-gate promotion is authorized. Keep the existing `UNVERIFIED`/`UNRESOLVED` fail-closed distinctions and all current STO-08 guards. Existing image insertion remains an independent, already reviewed *insert-only* operation; it must not be repurposed as a transform writer.

**Proposed work ownership:** EDT-14 developer owns selection geometry, rendering, input and session-history integration. The proposed division is: **STO-08 collaborator implements and tests the storage-owned restricted command**, subject to their explicit agreement and separately scoped authorization; **EDT-14 developer implements selection, renderer/input integration and coordinator/history handling**. Both review the boundary and final integration before C3. This is an ownership proposal, not permission to start storage work. Neither owner may implement merely because this ADR's architecture has been accepted; work ownership and checkpoint authorization remain pending.

## Alternatives considered

| Alternative | Why not recommended |
|---|---|
| Treat lasso as an enclosing axis-aligned rectangle or select by bounds alone | Fails the specified intersection-with-visible-geometry semantics for thin strokes/open shapes |
| Only implement ink + shapes, defer text/images | Useful intermediate checkpoint but does not satisfy issue #45 |
| Flatten mixed elements into bitmap/stroke paths before transforming | Destroys semantic editing, canonical IDs, stroke samples and media references |
| Rewrite every stroke sample/shape/text frame and font size on group scale | Higher drift, width/font inconsistency and representation risk compared with affine composition |
| Extend unrestricted `ReplaceElements` for arbitrary image JSON | Weakens the deliberate media writer boundary and permits asset substitution or ownership mistakes |
| Separate media and non-media commits | Can produce partial mixed moves and two undo/revision entries |
| New selection persistence table, second autosave queue or undo service | Duplicates authoritative state and breaks session chronology |
| Block all EDT-14 work until STO-08 closes | Unnecessary: C1/C2 design can proceed without asset mutations, while C3 remains gated |

## Consequences and tradeoffs

- Selection and transform geometry become a shared derived editor capability; the canonical model and v1 draft schema remain unchanged.
- Reusing guarded revision commits simplifies durable semantics but requires a **new, narrowly reviewed transform command** that cannot bypass media restrictions.
- Preserving transformations on the element envelope retains text styling, image crop and native ink data, but demands accurate transformed rendering and hit-testing under rotation/shear/reflection and small magnitudes.
- A retained-image transform preserves the typed edge and can use DB-only validation under the accepted INT-04 distinction; this proves **ownership preservation only**. Image reading/rendering independently needs approved leased integrity checks and bounded decode. Joint architectural approval of the distinction and gate policy is recorded above; API/budget design and implementation authorization remain required.
- Conservative page boundaries and cancellation can reject some edits to preexisting clipped content; that behavior must be visible and deterministic, not a silent geometry rewrite.
- No production text/image creation UI is implied. EDT-14 acceptance needs real typed rendering and synthetic persisted objects; later CNT issues implement rich content UX.
- Android-only test evidence does not certify Apple cross-platform rendering/format interoperability or physical stylus palm rejection.

## O1–O8 — **architectural dispositions accepted; remaining detailed decisions separately gated**

1. **O1 / INT-04 — Image integrity on a geometry-only edit:** Accepted **A: DB-only canonical/edge/finalized-metadata checks for the writer**, with no new lease and **no present-byte integrity claim**. Asset reading/rendering remains leased and strictly decoded. Both developers approved this architectural separation on 2026-11-11; C3 design and implementation authorization remain pending.
2. **O2 — Gate for retained owners:** Accepted direction: permit only **locally consistent `UNVERIFIED`** retained image owners in first writer; reject `UNRESOLVED`, `UNSAFE`, missing, invalid or unrecognized gate states, without index certification/repair. **Architectural gate policy accepted; C3 remains separately gated.**
3. **O3 — Lasso and transform limits:** Accepted architectural direction: platform touch slop for tap-vs-lasso, existing 8 dp body-hit tolerance, nondegenerate lasso, page-DU epsilon independent of zoom, positive finite uniform scaling with finite invertible and Float-renderable results. **Exact polygon epsilon, group anchor/degenerate policy, workload limits and per-gesture numeric thresholds remain open for C1/C5.** No new wire-schema limits.
4. **O4 — Preexisting clipped groups:** Accepted conservative **full-footprint containment for forward gestures** and last-valid previews. **Recorded exact undo/redo may restore clipped geometry**, with no generic bypass. This architectural split is accepted; C3/C5 implementation remains separately gated.
5. **O5 — Fully transparent and unavailable members:** Accepted direction: exclude whole-element opacity-zero objects from this tool, selecting nontransparent text/images by their transformed frame including transparent pixels, and explicitly rejecting page selection when unknown/unavailable geometry makes intersection indeterminate. **Detailed geometry/rendering design and execution remain gated by C1/C2.**
6. **O6 — Typed command, outcomes and history:** Accepted architectural direction: one typed page-space translation/uniform-scale plan with frozen exact persisted sources; repo-derived transforms; fully validated confirmed no-op, distinct definite rejection/committed/unconfirmed outcomes; internal exact history restoration of recorded envelopes; bounded parser/work and checked row counts. **Define exact Kotlin APIs/error codes/limits before C3/C4.**
7. **O7 — Rich rendering and asset reads:** The current `RegisteredFinalizedImageDecoder` returns metadata and **recycles its temporary bitmap**, not a retained view image. Accepted architectural direction: a distinct storage-reviewed lease-aware read/decode/cache boundary, maintaining current **16 MiB encoded, 4096 maximum dimension, 8,388,608 maximum pixels and 32 MiB bitmap budget**; accept only strict PNG and single-scan baseline JPEG.
